# Соглашения проекта

## Git-политика (из `AGENTS.md`)

- Коммиты и пуши — **только по явной команде пользователя**. Никаких самостоятельных `git commit`/`push`/`merge`/`rebase`.
- Перед коммитом показывать, какие файлы войдут (`git status`, `git diff`).
- Сообщение коммита — краткое, по делу, не длиннее ~140 символов.

## Качество кода (из `AGENTS.md`)

- Повторяющийся фрагмент (~5+ строк в 2+ местах) → выносить в общий метод/функцию или базовый класс. Не копировать логику между файлами — рассинхронизация правок и баги.

## Именование и стиль

Наблюдаемые в кодовой базе паттерны (Godot 4):

- Скрипты: snake_case (`grid_inventory.gd`, `chest_object.gd`).
- Классы (GDScript): PascalCase по умолчанию движка.
- Сцены: snake_case `.tscn` (имена ресурсов вида `rock_small.tres`, `bread.tscn`).
- Ресурсы предметов: snake_case `.tres`.
- Есть папки с пробелами: `interactable objects/`, `utility scripts/` — так и осталось, при новых путях стараться избегать пробелов.
- Autoload-имена — PascalCase без `_`: `ItemIcons`.
- Ноды рук экипировки: `RightHand`, `LeftHand`.
- Drag&drop в UI: строковые типы данных `"inventory"`, `"equipment"`, `"chest"`.

## Технологии

- Godot 4.7, GDScript, рендер GL Compatibility.
- Сеточные инвентари через `GridInventory` (`Dictionary[Vector2i, GridItem]`); для сундуков — подкласс `ChestInventory` (5x5).

## Дизайн-документы (не код)

- Концепция: `readme.md` (корень репозитория).
- Атрибуты/ресурсы/бестиарий/backlog: `doc/`.
- Изменения механик сначала обсуждаются в `doc/` и `tasks/`, код следует за ними.
